## 6. 收藏功能的口径问题（2026-09-18 排查记录）
- **现象**：用户反馈「收藏显示 1，点进去却什么都没有」。
- **两层原因**：
  1. `user/getProfile#stats.favCount` 直接 `favorites.where({userId}).count()`（数记录条数），
     而 `product/myFavorites` 会过滤掉「商品已删除」的条目 → 数字比列表多。
  2. 测试脚本收尾用 `myFavorites` 接口复核残留 —— 该接口会过滤已删除商品，
     **永远显示 0 条残留**（假阴性），于是留下一条指向已删测试商品的脏记录。
- **修法**：新增 `countValidFavorites()`（分批 join `products` 排除 `deleted`；
  云函数端 `_.in` 数组上限 **100**，必须分批）；`myFavorites` 遇到失效收藏顺手 `remove`（自愈）；
  复核一律**直接查集合** `wx.cloud.database().collection('favorites').count()`。

## 7. 跑腿与闲置共库的字段约定
- 两者**共用 `products` 集合**，靠 `type` 字段区分（`'errand'` / `'goods'`，老数据无 `type`）。
- 闲置侧查询必须用 `_.neq('errand')`，**不能用** `eq('goods')`（老数据会集体消失）。
- `errandStatus`：open / taken / done / canceled ↔ `status`：on_sale / trading / done / off_shelf。
- **同一个 `on_sale`，闲置叫「在售」、跑腿叫「待接单」** —— 文案表必须分开
  （前端映射在 `miniprogram/utils/constants.js#ERRAND_STATUS_TEXT`）。
- 接单必须用**带条件的原子更新**：`where({status:'on_sale', errandStatus:'open'}).update()`。
  「先查再改」会让两个人同时接单都成功。
- 跑腿可不配图（`images: []`，卡片走 `.pcard-img-errand` 占位）；**闲置必须有图**（无图 → 40001）。

## 8. `<text>` 内容跨行会多出一个空行（2026-09-18 排查记录）

**用户反馈**：「我的」页「已认证」三个字位置不对、偏出来了。

**排查过程（值得复用的手法）**：

1. 先量元素几何（`page.$('.name-tag')` → `offset()` / `size()` / `style()`）：
   胶囊盒 `top=44 h=18 中心y=53`，昵称 `top=39.5 h=27 中心y=53` → **盒子中心完全重合（差 0.00px）**。
   说明「盒子」没偏，问题在盒子**里面**。
2. 再量像素（Pillow 截图上按颜色取样）：
   ```
   修复前：胶囊 y 189..212（24px，中心 200.5）
          文字 y 202..212（中心 207.0）→ 文字中心 − 胶囊中心 = +6.5px
          顶部留白 13px / 底部留白 0px   ← 字贴着底边，还溢出
   修复后：文字 y 194..206（中心 200.0）→ −0.5px，上留白 5px / 下留白 6px（对称）
   ```
3. 根因：`mine.wxml` 里

   ```xml
   <text class="tag {{verifyClass}} name-tag" catchtap="goVerify">
     {{verifyText}}
   </text>
   ```

   **微信 `<text>` 把内容里的换行当成换行符渲染**（不是折叠成空格）→ 内容变成两行
   （第一行空、第二行才是「已认证」）→ 固定高度 18px 的胶囊里，文字被压到下半格并溢出底边。
   对照：`userProfile.wxml` 写成 `<text class="tag ...">{{verifyText}}</text>`（同行），一直正常。

**修复**：内容与标签写在同一行。全项目共 8 处同类写法（我的 `mine` 徽章 + 认证引导卡片、
`adminProducts` 状态徽章、`detail`/`publish` 的安全提示、`login` 的协议文案、`publish` 的 tip）。

**守卫**：`tools/e2e-test.cjs` 新增静态断言「`<text>` 内容未跨行」（正则
`/<text(?=[\s>])[^>]*>[ \t]*\r?\n/` 与 `/\r?\n[ \t]*<\/text>/`，`<textarea>` 的多行属性不算），
和「源码全为合法 UTF-8」并列。`<view>` 不受影响（空白正常折叠，已用发布页选择行截图实证）。

**小坑提醒**：写这类排查脚本时，`mini.evaluate` 里 `wx.createSelectorQuery().exec()` 拿到的
`boundingClientRect` 是宿主对象，直接 `return` 会报 `An object could not be cloned` ——
要么 `JSON.stringify` 后返回，要么改用 `page.$` + `element.offset()/size()/style()`（本项目后来用后者）。

**工具改进**：`tools/shot-pages.cjs` 增加「发布页下半屏」截图（`12b-publish-bottom`）——
分类 / 面交地点 / 价格这一屏以前从没被截过，而这类「文字被顶下去」的问题恰好只在下半屏看得出来。

## 9. 面交地点：改成用户自由填写（2026-09-18）

**为什么**：原来 `config.js` 维护一份 `tradePlaces` 白名单、发布页用 picker 选。校园地点太多，
固定列表永远不够用（「三食堂后门快递架旁边那棵树」塞不进任何选项），用户要求改成自己打字描述。

**改了什么**
- `pages/publish/publish.wxml`：「面交地点」由 `<picker>` → `<input>`
  （`data-field="tradePlace"`、`maxlength="30"`，与跑腿的取件地 / 送达地同一写法）。分类仍是 picker。
- `pages/publish/publish.js`：删掉 `onPlaceChange` 与 `tradePlaces` 引用；校验文案「请选择」→「请填写」；
  提交前 `trim()`。
- `config.js#tradePlaces`、`utils/constants.js#TRADE_PLACES` **已删除**（留着会让后来人以为还要配）。
- 云函数 `product/publish` 兜底（自由文本必须自己把关，以前是白名单、天然受控）：
  `normPlace()` 统一 trim；纯空格 = 未填（40001）；超 30 字（40003）；地点文本一并进本地黑名单
  与微信内容安全检测（它会显示在详情页和列表卡片上）。跑腿的 `fromPlace` / `toPlace` 同一套处理。

**字段口径**：`tradePlace` 仍必填；跑腿时存送达地 `toPlace`（卡片 📍 显示的就是它）。

**守卫**：e2e 新增 1 条静态（发布页必须是 input、不得再出现 `tradePlaces`）+ 3 条动态
（自定义描述写入 → 详情 / 列表原样回显、纯空格被拒、超 30 字被拒）。

**排版结论**：30 字以内的地点在详情页正常换行（`.place-row` 够宽），不需要额外截断。

## 10. 组件样式隔离：`app.wxss` 的 class 对组件内部**不生效**（2026-09-18 排查记录）

**现象**：面交地点放开自由输入后，首页卡片上的长地点把卡片撑成 3 行，价格也不是红色。

**根因**：自定义组件默认 `styleIsolation: isolated` ——
**`app.wxss` 里的 class 选择器不会作用到组件内部**（只有「标签名选择器」能穿透）。
`product-card/index.wxml` 一直在用全局的 `.ellipsis` / `.ellipsis-2` / `.price` / `.price-symbol` /
`.price-num` / `.price-ori` / `.row` —— **一条都没生效**。因为界面「差不多看着也对」
（价格黑色也能看、标题本来也就两行），所以长期没人发现。

**怎么确诊的**（别靠肉眼猜，缩略图会骗人）：
1. 放大截图看卡片 → 地点换了 3 行 = `white-space: nowrap` 显然没生效；
2. 可「价格看着明明发红」→ 自相矛盾。**改用像素采样**：卡片区红色像素只有 19 个、颜色
   `(239,55,112)`（这是 📍 emoji 的抗锯齿），不是 `#fa5151` = `(250,81,81)` → 价格其实是黑的。
3. 修完同一采样：红色像素 **361 个**、颜色正是 `(250,81,81)` ✓

**修法**：组件要用的样式写在**组件自己的 wxss** 里（`product-card/index.wxss` 末尾成组重复了
`app.wxss` 的那几个类，并注明「故意重复、别删」）；另外 flex 子项需要 `min-width: 0`（或 `flex: 1`），
否则长文本宁可把容器撑高也不省略。

**守卫**：e2e 新增静态断言「组件不依赖全局样式类」—— 扫组件 wxml 里的 class，凡是 `app.wxss`
有定义、组件 wxss 里没有的，全部列出来（含 `{{}}` 的动态类跳过）。当前只有 `product-card` 与
`empty-state` 两个组件，`empty-state` 只用自有类，不受影响。

**结论**：**新写自定义组件时不要引用全局 class。**

## 11. 「未来时间」被显示成「刚刚」（2026-09-18）

**现象**：跑腿任务卡片右下角显示「截止 **刚刚**」，详情页显示「**刚刚** 前」——
不管截止时间还剩几小时都一样。用户完全看不出任务什么时候到期。

**根因**：`utils/util.js#formatTime` 是**过去时间**语义：

```js
const diff = now.getTime() - date.getTime();
if (diff < 60 * 1000) return '刚刚';   // ← 未来时间 diff 为负，永远命中这一条
```

而卡片（`product-card/index.js`）与详情页（`detail.js`）把它用在**未来**的 `deadline` 上：
`截止 ${formatTime(item.deadline)}`。

**修法**：`util.js` 新增 `formatDeadline(input, short)` ——
当天 `今天 18:00`；次日 `明天 12:30`；更远 `9月20日 18:00`（卡片传 `short=true` 时只到「日」，
省出卡片右下角的空间）；已过期 `已截止`。卡片与详情页都改用 `formatDeadline`。

**守卫**：e2e 新增 2 条 —— ① 纯函数断言（3 小时后不得含「刚刚」，另测明天 / 已截止 / 短格式分支）；
② 页面级断言（详情页 `data.deadlineText` 渲染出来的不是「刚刚」）。

**判据**：**凡是显示「未来时间」，先确认这个格式化函数是过去语义还是未来语义** ——
两者对 `diff` 符号的处理正好相反，混用不报错、只静默显示成「刚刚」。
